List<simple record> — Form Item Mockups

Three UI approaches, each shown for three attribute sizes. The blue-bordered area is the List<simple record> form item, shown in context within a larger resource form.

Attribute sizes used:

  • Small (2 attrs) — wm-security-mapping-users: from(S), to(S)
  • Medium (5 attrs) — global-modules: name(S), slot(S), annotations(B), services(B), meta-inf(B)
  • Large (12 attrs) — match-rules: match-abstract-type(S), match-abstract-type-authority(S), match-host(S), match-local-security-domain(S), match-no-user(B), match-path(S), match-port(I), match-protocol(S), match-urn(S), match-user(S), authentication-configuration(S), ssl-context(S)

Approach A: Inline DataList

Each record is a row showing attribute values as name: value pairs. Edit/remove buttons on the right. An "Add" button at the bottom opens a blank inline form. Clicking edit expands the row into an inline edit form. The form fields are generated by the pipeline (same form items used elsewhere).

Approach B: Expandable Rows (Accordion-style)

Each record is a collapsible row. Collapsed state shows a title (first/primary attribute) and a subtitle summary. Expanded state shows all attributes as a description list plus edit/remove actions. Editing replaces the description list with form fields. Less dense than Approach A but scales better for large attribute counts.

Approach C: Label Group + Panel

Existing records are shown as clickable labels/chips. Clicking a label opens an inline panel below with the record details and edit form. An "Add" button opens a blank panel. Remove via ✕ on each label. Most compact in default state.
